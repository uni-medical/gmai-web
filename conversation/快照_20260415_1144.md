**核心任务**：维护 GMAI Lab (General Medical AI) 研究组官方网站，持续更新项目页面、论文列表、新闻、成员信息，并确保英中双语同步。

**全局约束与技术栈**：
- **Jekyll 4** 静态站点，托管于 **GitHub Pages**，零自定义插件（受 GitHub Pages 白名单限制）
- **无 Node/npm**：SCSS 由 Jekyll 内置 Sass 编译，不引入构建工具链
- **双语架构**：`/` 为英文树，`/zh/` 为中文树；`lang: en/zh` 在 front matter 声明；UI 字符串由 `_data/strings.yml` 驱动，数据文件（projects/publications/news）共用，仅 UI 文本翻译
- **数据驱动原则**：内容编辑只动 `_data/*.yml`；homepage 四个研究面板（vis-neural / vis-genomics / vis-molecular / vis-clinical）是 **故意硬编码** 在 `index.md` 中，不从 `projects.yml` 自动生成
- **SCSS 分层**：`_variables.scss`（设计 token）→ `_base.scss`（reset/nav/footer）→ `_components.scss`（内页）→ `_home.scss`（首页专用）。禁止将首页样式写入 `_components.scss`
- **图片策略**：所有图片必须先经 `bash scripts/optimize-images.sh` 生成 WebP，然后通过 `{% include picture.html %}` 引用
- **部署**：push 到 `main` → GitHub Actions (`.github/workflows/deploy.yml`) 自动构建并部署
- **本地预览**：`bundle exec jekyll serve --baseurl ""`（必须加 `--baseurl ""`）

## 4. 避坑档案（受阻/废弃方案）

### 4.1 projects.yml 的 Unicode 字面量陷阱
- **问题**：文件中 F²TTA 的 `²` 以 **字面量 `\u00B2`** 存储（非 UTF-8 实际字符），导致 Edit 工具的字符串匹配失败（匹配时使用的是 Unicode 字符 `²`，与文件中的转义序列不一致）
- **解法**：改用 Python 脚本按行号精确删除（`lines[252:271]`），绕过字符编码匹配问题
- **教训**：未来编辑含特殊字符的 YAML 条目时，先用 `python3 -c "with open(...) as f: lines = f.readlines(); [print(i,repr(l)) for i,l in enumerate(lines[N:M],N)]"` 查看原始字节再操作

### 4.2 `gh` CLI 不可用
- 当前环境未安装 `gh`（GitHub CLI），`/review` skill 执行时 fallback 到 `git diff HEAD~1 HEAD`
- 如需 PR 操作，需手动通过 GitHub Web 界面或在安装了 `gh` 的环境中操作

### 4.3 homepage 面板不可自动化
- homepage 研究面板设计上是**故意不从 `projects.yml` 自动生成**的，因为需要精细的视觉控制
- 曾有过讨论是否自动化 → 结论：维持硬编码，改动 homepage 面板只能手动编辑 `index.md` 和 `zh/index.md`
